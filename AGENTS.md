# AGENTS.md: GoQulient

VS Code extension (TypeScript) that browses PostgreSQL, MySQL/MariaDB and MongoDB databases, plus the Rust database
engine it spawns (a library crate and a stdio JSON-RPC server). The engine is a Rust port of GokuCore, the engine of the
Goku macOS app; the two are kept in step by shared JSON fixtures. Start here before fixing a bug or adding a feature.

## Layout
```
engine/                     Cargo workspace (toolchain pinned in rust-toolchain.toml)
  crates/goku-engine/         library: drivers, safety primitives, introspection, Mongo inference, ER layout
  crates/goku-engine-server/  stdio JSON-RPC server (LSP framing) the extension spawns
vscode/                     the extension: engine client, connections, sidebar tree, webviews (table, ER diagram)
  test/  test-e2e/            Node unit tests; end-to-end test in a real VS Code
  webview-dev/                browser harness for the webviews (fake host, Playwright screenshots)
parity/                     JSON fixtures generated by the Goku app's test suite; never edited here
docker/, docker-compose.yml test databases (seeds in docker/*/init) and the e2e image; compose `goqulient`, one per worktree
scripts/dev.sh              every build and test command, in Docker
docs/                       ARCHITECTURE.md, TESTING.md, RELEASING.md, PUBLISHING.md
```

## Commands
```bash
scripts/dev.sh up                    # test databases + engine/vscode tool containers
scripts/dev.sh engine test [filter]  # unit, integration and parity tests
scripts/dev.sh engine check          # rustfmt --check + clippy -D warnings
scripts/dev.sh vscode test           # typecheck + Node tests against the engine's debug build
scripts/dev.sh vscode e2e            # the extension inside a real VS Code (xvfb) against the test databases
scripts/dev.sh down                  # remove containers and volumes
```
More (build, shell, run, screenshots, Atlas): [docs/TESTING.md](docs/TESTING.md).

## Rules
1. **Docker only.** Cargo, npm and every test run inside the compose project's containers (`scripts/dev.sh`). Don't
   install toolchains on the host to run them. Native macOS and Windows builds happen in CI.
2. **The test databases are shared and throwaway.** Tests create scratch objects with random suffixes (`rs_pg_*`,
   `rs_my_*`, `rs_mg_*`) and drop them; the end-to-end test only reads. Don't run two test runs at once in one checkout
   (each git worktree gets its own compose project and ports, [docs/TESTING.md](docs/TESTING.md#parallel-worktrees)).
   Never point tests at a real database.
3. **Safety is a product requirement** (see [Safety](#safety)). Don't weaken it to make a feature or a test easier.
4. **Profiles decode tolerantly** (see [Profiles](#profiles)).
5. **Parity fixtures are generated, not written.** `parity/` comes from the Goku app's test suite. Don't edit it by
   hand or regenerate it here; if a parity test fails, the Rust side is wrong. Changes arrive as a sync PR from the app's
   repository ([docs/TESTING.md](docs/TESTING.md#parity-fixtures)).
6. **Every behaviour change comes with a test**: Rust unit tests next to the code, protocol tests in
   `goku-engine-server/src/tests.rs`, driver tests in `engine/crates/goku-engine/tests/` (`support::profile(kind)`,
   `support::run`), Node tests in `vscode/test/`, and `vscode/test-e2e/suite.cjs` when it needs a database and a real
   VS Code. For webview changes, take screenshots (harness or `GOKU_E2E_SCREENSHOTS`) and look at them.
7. **Match the surrounding code**: dense, few comments that explain *why*; `DbError` + `display_message()` for
   user-facing errors; `cargo fmt` (max width 120). Comments that say "port of GokuCore's `X`" name a file in the Goku
   app's repository as plain text, never as a link.
8. **Conventional Commits** (`feat:`, `fix:`, `docs:`, `feat!:` …): release-please builds the changelog and the version
   from them ([docs/RELEASING.md](docs/RELEASING.md)).
9. **Update the docs in the same change** when you change behaviour, the protocol or a file's role
   ([docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) has the file map, the protocol table and checklists).

### Safety
The engine carries the Goku app's safety promise: don't hang or crash the user's machine, don't hurt the database, don't
leak secrets.
- Every network wait goes through `deadline::with_deadline`, whose `on_timeout` closes the socket or cancels the server
  query; server-side limits too (`statement_timeout`, `max_execution_time`, `maxTimeMS`).
- Rows are streamed and capped (`limits::RowCollector`: default 1,000, hard cap 100,000) and long cells are clipped.
  Nothing loads a whole result into memory.
- Read-only is enforced twice: the client check **and** the server session (`default_transaction_read_only`,
  `SET SESSION TRANSACTION READ ONLY`). MongoDB has no server-side read-only, so its client check must stay strict.
- Destructive statements need explicit confirmation (`needsConfirmation`), once the query editor exists.
- A grid edit must hit exactly one row, or the whole batch rolls back, once editing exists.
- One tokio runtime per process, built by the server; the library never creates a runtime and never prints. stdout
  carries only protocol frames.
- Secrets live only in VS Code's SecretStorage (or memory, if the user chose so) and reach the engine only over stdin:
  never in settings, argv, environment variables, logs, error messages, tree labels or webview HTML. Endpoints and
  statements are redacted (`redact.rs`, `vscode/src/connections/redact.ts`, same rules on both sides).

### Profiles
Saved connections must survive version changes. `ConnectionProfile` (`profile.rs`, and `vscode/src/connections/` for
settings) decodes tolerantly: missing fields get their defaults, unknown enum cases a safe fallback (an unknown SSL mode
becomes the strictest), and entries that still can't be read stay in the list as invalid, unchanged. When you add a
field, give it a default in `from_fields`, add a test, and keep the JSON shape the same as the Goku app's.

## Common tasks → start points
- **Any Rust change in `engine/`:** follow the project skill [`.claude/skills/rust-engine/SKILL.md`](.claude/skills/rust-engine/SKILL.md).
- **Bug in a result or a cell's text:** `engine/crates/goku-engine/src/drivers/<engine>/` (`format.rs` for cell text).
- **New protocol method / tree node type:** the checklists in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#checklists).
- **New connection setting or `.env` variable:** `profile.rs` + `vscode/src/connections/` ([docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#connections-in-vs-code)).
- **Webview change:** `vscode/webview/` (pure helpers in `webview/lib/`), the panel in `vscode/src/views/`; check it in
  the dev harness.
